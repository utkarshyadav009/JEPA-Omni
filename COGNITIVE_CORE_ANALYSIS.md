# Cognitive core: right models for the job (2026-08-08)

Answers your brain-dump questions: do we need 700M for the fast tier, is the 1B thinker
redundant, where should tool-calling live, what does the thinker do + what data it needs.

## 1. Fast tier: 350M beats 700M for this role — switch to it
Real Jetson benchmark (llama.cpp, Q8_0, services off):

| | LFM2.5-**350M** | LFM2-700M v9 (current) |
|---|---|---|
| Fast-tier response (24 tok) | **231 ms** | 405 ms |
| Per-token | **9.6 ms** | 16.9 ms |
| Load | **466 ms** | 890 ms |
| Weights on disk | **362 MB** | 755 MB |
| Memory footprint | **~half** | baseline |

The fast tier ("System 1") only produces short conversational replies (24-token budget) and
escalates hard ones — it does not need 700M of capacity. The 350M nearly **halves latency
and memory**. **Recommendation: switch the fast tier to LFM2.5-350M, retrain on the BMO
corpus.** Frees ~half the fast-tier memory (headroom you asked about) and speeds every reply.
Caveat: verify quality after the BMO retrain (350M has less raw capacity; personality +
short-turn quality should hold, but confirm on a held-out set).

## 2. The 1B "thinker" IS redundant as currently built — the real question
What the code actually does (`m4_cognitive_core.py`): the fast tier greedy-decodes with
per-token logprobs → mean NLL = confidence. The `CognitiveCoreRouter` escalates to the
thinker (MiniCPM5-1B) when confidence is low (NLL > 3.0) or for a few always-escalate intents.
**But `enable_thinking=False`** — reasoning is OFF because MiniCPM's think-mode spends the
short token budget on a `<think>` preamble and never reaches an answer, and it's slow
(measured **12.2s / 60 tokens** in the full stack). So today the "thinker" is **just a bigger
System-1 model with the SAME corpus and character** — which is exactly your redundancy worry,
and the literature agrees: a second tier only earns its cost if it does something DIFFERENT
(deliberate System-2 reasoning), not merely "bigger." A same-corpus bigger model buys little.

Two coherent paths (your call — this is a product/architecture decision):

- **Option A — Drop the thinker (simplest).** Run only the 350M fast tier for companion
  turns. Escalation is rare and a same-corpus bigger model's marginal quality gain is small.
  Maximum memory headroom + simplest system. Add the thinker back only when a real reasoning
  need appears.
- **Option B — Make it a REAL System 2.** Keep a small model as the thinker but train it on
  DIFFERENT data — reasoning/deliberation, not the conversational corpus — and accept the
  escalated-turn latency (the literature's expected "bimodal" slow tail). It handles: complex
  planning, multi-step **tool orchestration**, and (eventually) the AV-grounded path
  (`m4_duplex_loop.py`, currently unwired). The 350M's freed memory could let this stay
  resident instead of lazy-loading.

## 3. Where tool-calling belongs
Split by complexity:
- **Simple single-tool calls** (weather, time, timer) → **fast tier** (System 1). It already
  emits `<tool_call ...>`; the dispatcher (`models/m5_tools.py`) executes. Low latency, no
  thinker needed.
- **Complex / multi-step orchestration** ("check the weather AND if it's raining set a
  reminder") → **thinker** (System 2), if you keep one. This is deliberate planning, exactly
  what a reasoning tier is for.
So tool-calling is NOT "the thinker's job" wholesale — simple calls stay fast; only
orchestration escalates.

## UPDATE (2026-08-08): M3 perception connector is DROPPED
Earlier this doc noted the thinker had to be 1536-hidden to match the M3 connector's
projection into the LLM. The user has dropped the M3 (world-state-token) approach; perception
is now the newer prediction/embedding-alignment style (V-JEPA-like, EmbeddingGemma space),
integrated differently (details TBD). **So the thinker model is NOT constrained to 1536
hidden.** The `DeepSeek-R1-Distill-Qwen-1.5B` recommendation stands on its own merits
(reasoning-distilled, chain-of-thought, fits Jetson lazy-loaded, background-run so slow CoT
is fine) — just no longer forced by M3. How the thinker consumes perception will follow the
new prediction-style integration.

## 4. What a real thinker needs for training data (if Option B)
NOT the fast tier's conversational corpus (that's what makes it redundant). Instead:
- **Chain-of-thought / deliberation traces** for BMO-appropriate hard turns (reason then
  answer), so it learns to think before responding.
- **Tool-orchestration examples**: multi-step plans that call several tools in sequence and
  use their results.
- **Grounded-reasoning examples**: using perception/memory state to reason.
- Best generated by **distilling from a larger reasoning model** (System-2 → System-1
  distillation, per the literature) — e.g. have GPT-OSS-120B produce CoT traces for BMO
  scenarios. This is a distinct corpus + training objective from the fast tier's.

## DECIDED (2026-08-08): 350M fast tier + Qwen3-0.6B thinker
Jetson benchmarks settled it (llama.cpp, per-token from a 100-token gen; ~300-tok CoT est.):

| model | role | per-token | peak mem | ~300-tok CoT |
|---|---|---|---|---|
| **LFM2.5-350M** (retrained) | fast tier | **9.4ms** | +59MB | — |
| **Qwen3-0.6B** | thinker | **18.2ms** | +460MB | **~5.5s** |
| MiniCPM5-1B (old thinker) | — | 22.1ms | +389MB | ~6.6s |
| DeepSeek-R1-Distill-Qwen-1.5B Q4 | — | 26.5ms | +517MB | ~8s |
| DeepSeek-1.5B Q8 | — | 33.6ms | +1.3GB | ~10s (too heavy) |

**Qwen3-0.6B wins the thinker slot**: fastest per-token, smallest, AND reasoning-capable
(native `/think` mode) — beats both the 1.5B reasoners (heavier/slower) and the old MiniCPM5-1B
(not a reasoner). Fine-tune it on the thinker corpus (CoT + orchestration + grounded). Replaces
MiniCPM5-1B as the reasoning tier.

## Recommendation summary
1. **Fast tier → LFM2.5-350M** (retrain on BMO corpus). Clear win, do it.
2. **Thinker → decide A vs B.** If you want BMO to genuinely *reason/plan/orchestrate tools*,
   Option B with a dedicated reasoning corpus. If you want simplest + lightest now, Option A
   (drop it) and revisit. Either way the current same-corpus 1B is not pulling its weight.
3. **Tool-calling**: simple → fast tier (already works via the dispatcher); orchestration →
   thinker (only under Option B).
